# impatient-programming

A philosophy like Extreme Programming, rebuilt for the agent era.

## What this is

Extreme Programming answered a simple question for its time. What changes when code is written by people in a room together, all day, at human speed? Impatient Programming answers the same question for a different room. The room now holds one human and a fleet of agents, the code arrives at machine speed, and the bottleneck moved. The bottleneck is no longer typing. It is waiting, and it is human attention.

The first sketch of the values looks like this.

- Waiting is the only waste. An idle agent is a stalled line, and a stalled line is a defect in the system rather than a fact of life.
- Human attention is the budget. Everything else is cheap and getting cheaper. Spend the human on judgement and spend the machines on everything else.
- Never idle. If an agent can work, it works. If it cannot work, the reason gets named, logged, and treated as a bug.
- Code is disposable. Regeneration beats repair when repair costs more attention than the code is worth.
- Verification replaces trust. Claims get checked against evidence, every time, no matter who or what made them.

SwarmOps is the operations discipline of this philosophy. Impatient Programming says how agent-era work should feel. SwarmOps is how the fleet gets run, watched, budgeted, and refined so that the feeling survives contact with production.
